# AIエージェント実験場

メインエージェント、サブエージェント、関連リソースをどう組み替えたら
全体としてどういう挙動になるかを頻繁に組み替えながら実験するためのリポジトリ。

ユースケース単位で単一のエージェントを提供するサービスはたくさんあるが、
内側のサブエージェントを細かく操作できるものがなかなかないので独自に構築している。

## UI

UIは主に React Flow を使用する。

ノード
- メインエージェント。
- サブエージェント。最低でも OpenRouter の無料モデルと Jev を使う想定。
- リソース。実験なのでjson固定の想定。
  実運用上のストレージやデータベースやファイルシステムの任意のファイルに相当するもの。
- Web検索。

エッジ
- エージェントからエージェントへのエッジはツールコール
- エージェントからリソースやWeb検索へのエッジはそのリソースの参照権限ないし編集権限

ノードもエッジも今後どんどん増えていくので拡張性が高くないとだめ。

ユーザーとAIとのインターフェースは普通のチャットの想定。
Abort, 過去ターン前からのやり直し、が可能。

## ワークフォルダとワークファイル

チャットセッションは1つのワークフォルダを与えられる。
AIは json or markdown の好きなファイルを作成できる。
ユーザーはここを編集できないが、チャット欄併設のファイルツリーの様なUIで閲覧できる。
チャットの過去ターン前からのやり直しがあるのでスナップショットの仕組みが必要。

## ログ

内部の挙動を確認しやすいよう、ログがGUI上で見える必要がある。

## 設計方針

### モデル

- メインエージェント・LLMサブエージェントともに、ノードごとにプロバイダとモデルを自由に選べる。
  プロバイダは OpenRouter。
- Jev（TypeSafe AI）はテキスト生成もツールコールもできない判定専用モデルなので、
  LLMサブエージェントとは別の「判定ノード」として扱う。
  - 接続は公式SDK `@typesafe-ai/sdk` の `TypeSafeClient.systemOne()` を直接使う。
  - 質問（noul / choice / score）はノード側でUIから固定定義する。
    呼び出し側のエージェントは state だけを渡し、確率・confidence 付きの型付き結果を受け取る。
  - Jev ノードからは他ノードへエッジを張れない。
  - 入力は state と質問を合わせて約32,000トークンまで。数値比較や日付計算は苦手なのでコード側で行う。
- OpenRouter のモデル候補は、モデル一覧APIから対応機能と料金ごと取得する。
  ツールコール非対応のモデルも選べるが、そのノードから出るエッジがあればグラフ上で警告する
  （ツールを持たないテキスト生成だけのサブエージェントなら問題ない）。
- Web検索ノードの実体は Tavily。どのモデルからも同じツールとして使える。

### エージェント間の呼び出し

- 以下はエッジの属性で設定する。ノード側には既定値だけを持たせる。
  - 何を渡すか（タスク文字列のみ / 親の会話履歴も渡す）
  - 何を返すか（最終テキストのみ / 全ステップ）
  - サブエージェントの記憶（毎回まっさら / 同一ターン内で継続 / セッションを通して継続）
- サブ→サブの呼び出しも可能。呼び出しのネストには、循環の有無に関係なく一律の深さ上限
  （初期値5、変更可）をかけ、上限に達したら打ち切る。
- ツールは逐次実行のみとし、並列実行はしない。そのため書き込みの競合は起きない。
- 参照権限・編集権限はエッジの属性で持つ。

### セッションとやり直し

- グラフ構成は名前を付けて複数保存でき、セッションはそのうち1つを参照する。
- 過去ターンからのやり直しは元の会話を消さず、分岐として残すツリー構造にする。
  - やり直しの操作は「発言を編集して再送信」と「同じ発言で再実行」の2つ。
  - 分岐は切り替えて閲覧する。並べて比較する専用画面は作らない。
- グラフはセッション途中でも編集でき、次のターンから反映する。
  各ターンには実行時のグラフを記録し、「構成だけ変えて同じ質問」を分岐で比較できるようにする。
  分岐して実行するときは、そのターンのグラフではなく現在のグラフを使う。
- Abort すると実行中のサブエージェントも含めて止め、それまでの出力は残す。

### ワークフォルダとリソース

- ワークフォルダは実ファイルではなく、SQLite 上の仮想ファイルシステムとしてターン単位で版管理する。
  分岐ごとのスナップショットもこの仕組みで扱う。
- ワークフォルダもノードにして、エッジで参照・編集の権限を付与する。
- リソースノードの json はセッション開始時にコピーし、編集はそのセッション内だけに効く。
  やり直しではワークフォルダと一緒に巻き戻る。
- ワークフォルダとリソースを操作するツールは、一覧・読み取り・全文上書き・削除に加えて
  部分編集を持つ。部分編集は、Markdown なら文字列置換、JSON なら JSON Patch で行う。

### 永続化

- グラフ構成・セッション・仮想ファイルシステム・ログはすべて SQLite に保存する。
- SQLite には better-sqlite3 と Drizzle を使う。
- 自分一人がローカルで使う前提で、認証は付けない。

### 実行と通信

- エージェントの実行はサーバー側で進める。LLMの呼び出しには AI SDK Core を使う。
- サーバーからUIへは、独自に定義したイベントを SSE で配信する。
  イベントにはステップ・ツールコール・ログ・ファイル変更があり、呼び出しの親子関係も含む。
- Abort は SSE とは別のAPIで指示する。
- AI SDK の useChat（`@ai-sdk/react`）は使わない。

### 画面構成

- 境界をドラッグしてサイズを変えられる分割ペインにする。Allotmentを使用。
  左にグラフ、中央にチャット、右にファイルツリー、下にログを置く。

### ログと表示

- ログパネルには以下を表示する。
  - ツールコールの入出力（サブエージェントの内部ステップを含む）
  - LLMへの生のリクエスト/レスポンス（システムプロンプト・履歴・ツール定義を含む全文）
  - ノード別・ターン別のトークン数、コスト、所要時間
- チャット欄ではサブエージェントの途中経過を折りたたみの入れ子で表示する。

## 実装の順序

1. 骨格：グラフの保存・編集、メイン→サブのツールコール（OpenRouter）、
   SQLite への永続化、ログパネル、Abort
2. ワークフォルダと版管理
3. 分岐（やり直し）
4. リソースノードと Web検索（Tavily）
5. Jev
